Top Spin FE Wrapper Protocol v4.5
TOP SPIN FE WRAPPER PROTOCOL

Integrate your game with Top Spin

The Top Spin FE Wrapper Protocol enables communication between a game frontend and the embedding Top Spin wrapper through the window.postMessage() Web API.

Get started → View complete flow
i
Game FE drives initialization

The game starts Wrapper Protocol communication by sending mode:init. Top Spin does not send an initialization command before this message.

Getting started

Integration overview

Communication is bidirectional. The game FE sends its current modes, states and events to Top Spin, while Top Spin sends actions to the game FE when it needs the game to perform an operation.

GAME FE → TOP SPIN

Game messages

Configuration, modes, states and events describe the current state of the game.

configmodestateevent
TOP SPIN → GAME FE

Top Spin commands

Actions request an operation from the game, such as changing the bet or starting a spin.

action
Getting started

How the wrapper works — from zero

Think of Top Spin and the provider game as two separate applications. The provider game runs inside an iframe. The Wrapper Protocol is simply the language they use to tell each other what is happening.

The simplest possible explanation
Top SpinCreates the place where the game will run and controls the surrounding UI.
→
Provider gameLoads inside the iframe, loads its own assets and starts itself.
→
Wrapper ProtocolKeeps both sides synchronized using postMessage().

Who is responsible for what?

TOP SPIN

The host / wrapper

Top Spin opens the provider game, shows its own loader and UI, listens for messages from the game and sends actions when the player uses Top Spin controls.

  • Creates the game iframe
  • Shows the Top Spin preloader while the iframe is loading
  • Receives config, mode, state and event messages
  • Sends action messages to the provider game
  • Keeps Top Spin UI synchronized with the provider game
PROVIDER GAME

The actual game

The provider owns the game application inside the iframe. It loads its assets, initializes the game and reports its current status to Top Spin.

  • Loads game code, graphics, sounds and other provider assets
  • Starts Wrapper Protocol communication with mode:init
  • Sends the game config
  • Reports modes, states, balance, bet and wins
  • Executes actions requested by Top Spin
i
The Wrapper Protocol does not load the game

The iframe and provider application are responsible for loading the game. The protocol is the communication layer between the already running provider game and Top Spin.

Getting started

What happens when a game is opened?

This is the startup process from the moment Top Spin receives the game URL until the game is ready for the first spin.

1
TOP SPIN

Top Spin prepares the game screen

Top Spin creates its preloader and starts the loading animation. At this point the provider game has not started Wrapper Protocol communication yet.

2
TOP SPIN

Top Spin creates the iframe

Top Spin creates an iframe using the provider's game URL and adds it to the page. The browser now starts loading the provider application.

3
PROVIDER

The provider application loads

The provider's HTML/JavaScript application starts loading inside the iframe. The provider is responsible for its own game assets — for example scripts, textures, images, fonts, audio and game data.

4
TOP SPIN

The iframe reports that it loaded

Top Spin handles the iframe load event, stops its preloader and removes the spinner. A provider may still perform additional asynchronous loading internally after this browser event.

5
PROVIDER

The game starts the Wrapper Protocol

When the provider wrapper is initialized, the game sends mode:init. Top Spin does not send an initial Wrapper Protocol command before this.

{"mode":{"name":"init","data":{}}}
6
PROVIDER

The game sends its configuration

Immediately after initialization, the provider sends config. Top Spin uses it to learn how this game works: current game mode, number of lines, available bets and other configuration data.

{"config":{...}}
7
PROVIDER

The game says it is ready

After configuration, the provider sends mode:ready. This tells Top Spin that initialization is complete.

{"mode":{"name":"ready","data":{}}}
8
PROVIDER

The game enters the pre-spin state

The provider sends state:beforeSpin, including the current balance. Top Spin now knows that the game is in the normal state before a spin.

{"state":{"name":"beforeSpin","data":{"balance":1000}}}
✓
READY

Initialization is complete

Both applications are now synchronized. Top Spin can send actions and the provider game can continue reporting state and event changes.

What is happening while assets are loading?

Top SpinProvider game
Shows the Top Spin loading spinner.Browser loads the provider URL inside the iframe.
Waits for the iframe and incoming Wrapper Protocol messages.Loads and initializes its own scripts, graphics, sounds and game resources.
Does not need to send an initial protocol action.When its wrapper is initialized, sends mode:init.
Processes the received configuration.Sends config, then mode:ready and state:beforeSpin.
!
Do not confuse iframe loading with protocol initialization

The browser's iframe load event and mode:init are different things. The first belongs to browser/page loading. mode:init belongs to the Top Spin Wrapper Protocol and must be sent by the provider game.

After initialization: who talks first?

Once the game is ready, communication becomes bidirectional. For example, when the player starts a spin through Top Spin, Top Spin sends an action. The provider executes it and reports what happens using mode, state and event messages.

Top Spinaction: spin→ Please start a spin.
Providermode: spin→ Spin mode started.
Providerstate: spinning→ Reels/game are spinning.
Providermode: win→ Optional: this spin has a win.
Providerevent: increaseWin→ Reports the cumulative win.
Providermode: ready→ Spin flow is finished.
Providerstate: beforeSpin→ Ready for the next spin.
Getting started

Quick start

Use the browser message event to listen for Top Spin commands and window.postMessage() to send Wrapper Protocol messages back to Top Spin.

Listen for messages from Top Spin

JavaScript
window.addEventListener("message", function(e) {
    try {
        var data = JSON.parse(e.data);

        if (data) {
            // Process Top Spin wrapper messages
        }
    } catch (e) {}
});

Send messages to Top Spin

JavaScript
var message;

// Create Wrapper Protocol JSON message
message = JSON.stringify({
    mode: {
        name: "init",
        data: {}
    }
});

window.postMessage(message, "*");
Game lifecycle

Initialization flow

When the game is opened, the game FE initiates the Wrapper Protocol. The required startup sequence is:

01 mode:init Game FE initializes
→
02 config Game configuration
→
03 mode:ready Game is ready
→
04 state:beforeSpin Ready for first spin
!
Do not wait for an initial Top Spin command

Before mode:init, the game should not wait for an action from Top Spin. The first Wrapper Protocol message is sent by the game FE.

Communication

Message structure

Wrapper Protocol messages are JSON objects. The top-level property identifies the message category.

TypeDirectionPurpose
configGame → TSProvides game configuration.
modeGame → TSDescribes the current high-level game mode.
stateGame → TSDescribes the current game state.
eventGame → TSReports changes such as balance, bet or win.
actionTS → GameRequests an operation from the game FE.
Messages

Config

The config message is sent by the game FE after mode:init. It provides Top Spin with game configuration such as total bet, active lines, game mode and the available bets for each game mode.

Example · fixed 5 lines
{
  "config": {
    "hitRateInfo": "1:13204807",
    "RTP": "95.13%",
    "totalBet": 100,
    "lines": 5,
    "gameMode": 0,
    "gameModeData": [
      {
        "gameMode": 0,
        "lines": 5,
        "bets": [5, 10, 15, 20, 25, 40, 50, 75, 100]
      }
    ]
  }
}
Messages

Mode messages

Mode messages communicate the current high-level phase of the game FE.

initWrapper initialization started.
readyGame is ready for normal interaction.
spinA spin has started.
winThe current spin produced a win.
bonusGameGame is in a bonus / Free Games phase.
errorGame entered an error state.
closedGame has closed.

Game lifecycle

Regular spin flow

When a regular spin starts, the game FE sends mode:spin followed by state:spinning.

Spin started
{"mode":{"name":"spin","data":{}}}
{"state":{"name":"spinning","data":{}}}

If the spin finishes without a win, the game returns to the normal pre-spin state:

No win
{"mode":{"name":"ready","data":{}}}
{"state":{"name":"beforeSpin","data":{"balance":1000}}}
Game lifecycle

Regular spin win

When a regular spin produces a win, send mode:win and then report the cumulative win with increaseWin. Once the game is ready again, return to mode:ready and state:beforeSpin.

Game FE → Top Spin
{"mode":{"name":"win","data":{}}}
{"event":{"name":"increaseWin","data":{"value":100}}}
{"mode":{"name":"ready","data":{}}}
{"state":{"name":"beforeSpin","data":{"balance":1000}}}
Game lifecycle

Free Games flow

When Free Games are won, the game first reports the win. Once the balance is updated and the first Free Game is ready, enter bonusGame mode and send freeGamesStart.

win→increaseWin→bonusGame→freeGamesStart
Start Free Games
{"mode":{"name":"win","data":{}}}
{"event":{"name":"increaseWin","data":{"value":100}}}
{"mode":{"name":"bonusGame","data":{}}}
{"state":{"name":"freeGamesStart","data":{"balance":1000,"totalRoundWin":0}}}

Spin inside Free Games

Free Game spin
{"mode":{"name":"spin","data":{}}}
{"state":{"name":"freeGamesSpinning","data":{}}}

End Free Games

Free Games end
{"mode":{"name":"ready","data":{}}}
{"state":{"name":"freeGamesEnd","data":{"balance":1000}}}
Game lifecycle

Balance updates

Each time the game FE updates its balance, it should send a balanceChange event to Top Spin.

Game FE → Top Spin
{"event":{"name":"balanceChange","data":{"value":1000}}}

If Top Spin explicitly requests a balance update, respond with the same balanceChange event containing the current value.

TOP SPIN → GAME FE {"action":{"name":"updateBalance"}}
→
GAME FE → TOP SPIN {"event":{"name":"balanceChange","data":{"value":1000}}}
Game lifecycle

Game closing

For unconventional or other reasons where the game needs to close, notify Top Spin with gameClosing followed by mode:closed.

Game FE → Top Spin
{"event":{"name":"gameClosing","data":{}}}
{"mode":{"name":"closed","data":{}}}
